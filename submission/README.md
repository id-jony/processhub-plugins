# Publication readiness

Status: **prepared, not submitted**. Do not describe local validation as directory approval.

## Release gates

1. Deploy the ProcessHub server changes: public `/privacy` and `/terms`, named tools, and
   the `processhub-claude-code` public OAuth client. Previously auto-generated default
   allowlists upgrade without key rotation; customized allowlists stay operator-owned.
2. Verify those URLs over HTTPS without a session. Verify OAuth metadata and execute all
   reviewer scenarios in a dedicated synthetic organization. Never provide real customer
   data to reviewers. Demo credentials must be delivered privately through the vendor portal.
3. Have the publisher review the legal text and current processing practices, including
   subprocessors, retention, consent and cross-border AI transfers. Do not promise legal
   certification or infer vendor approval from having policy URLs.
4. Publish this repository and install from its public Git URL in clean client profiles.
   Test a complete OAuth and report-approval flow in each target product. Codex CLI,
   Claude Code, Claude web and Cowork are distinct validation targets.
5. Capture sanitized screenshots and a short demo using synthetic data. Do not upload
   account tokens, personal user screenshots, private application code, or reviewer passwords.

## OpenAI directory

Use the current submission portal linked from the official documentation below. A
verified publisher identity and the required organization permissions are needed.
Supply listing.json, icon.png, HTTPS MCP URL, five positive and three negative scenarios,
and private reviewer access. Complete the domain challenge with the exact token provided
by the portal; no token is generated by this repository. Availability countries and final
terms acceptance must be set by the publisher. Enterprise domain restriction / UserInfo
requirements need separate compatibility review: this server does not expose OIDC email
scopes merely because it supports OAuth.

## Anthropic directories

The Claude Code/Cowork plugin directory and Claude Connectors Directory are different.
For the plugin submission provide the public GitHub repository and Claude package path.
For the connector submission provide the hosted MCP endpoint and the pre-registered
`processhub-claude` client information. Directory management and account eligibility must
be verified in the submitting account. Do not claim Cowork compatibility before its smoke
test; OAuth behavior may differ from Claude Code.
